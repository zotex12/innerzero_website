# Release-update email

Sends the "new version is out" email to the newsletter list
(`newsletter_subscribers` in Supabase). Built to be driven by the
`/release-update` runbook, but you can run it by hand too.

## Files

- `release.json` - the words for the current release. Edit this each release.
- `template.mjs` - the look (dark, branded HTML). Edit only to change design.
- `send.mjs` - the runner (dry run / test / send).
- `preview.html` - generated by a dry run. Open it in a browser to check.
- `.sent-log.json` - generated; records which versions were sent (stops double-sends).

## One-time setup

Add your Resend key to `.env.local` (it is also in Vercel, but the send
runs locally):

```
RESEND_API_KEY=re_your_key_here
```

The other keys it needs (`NEXT_PUBLIC_SUPABASE_URL`,
`SUPABASE_SERVICE_ROLE_KEY`, `NEXT_PUBLIC_SITE_URL`) are already in
`.env.local`.

The sending domain `innerzero.com` is verified in Resend and emails come
from `updates@innerzero.com`.

## Each release

1. Edit `release.json`: bump `version`, `dateLabel`, `subject`, `preheader`,
   `intro`, and the `New` / `Improved` / `Fixed` highlights. Keep it short;
   this is an email, not the full changelog.
2. Dry run and eyeball the preview:
   ```
   node --env-file=.env.local scripts/release-email/send.mjs
   ```
   Open `scripts/release-email/preview.html`.
3. Send one real test to yourself:
   ```
   node --env-file=.env.local scripts/release-email/send.mjs --test louie@innerzero.com
   ```
4. Send to everyone:
   ```
   node --env-file=.env.local scripts/release-email/send.mjs --send
   ```
   Add `--force` only if you really need to re-send a version.

## Notes

- Every email carries a working unsubscribe link and a one-click
  `List-Unsubscribe` header. Unsubscribes are handled at
  `/unsubscribe` on the live site.
- Resend free tier: 3,000 emails per month, 100 per day. Plenty for now.
- British English, no em dashes, no emojis, no "forever / always free /
  permanent" wording. Same rules as the rest of the site.
